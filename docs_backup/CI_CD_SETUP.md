# CI/CD Setup Guide

## Overview
This project uses GitHub Actions for continuous integration and deployment.

## Fixes Applied

### 1. Environment File Issue
**Problem**: The `.env` file is required as an asset but gitignored, causing CI builds to fail.

**Solution**: CI now automatically creates a `.env` file during builds with default values.

### 2. Firebase Configuration
**Problem**: `firebase_options.dart` was gitignored, making it unavailable in CI.

**Solution**: Removed `firebase_options.dart` from `.gitignore`. This is safe because:
- Firebase client API keys are meant to be public
- Firebase Security Rules protect your backend
- This is the recommended approach by Google/Firebase

## Required Secrets

Set these secrets in your GitHub repository (Settings → Secrets and variables → Actions):

### Android Build Secrets
- `ANDROID_KEYSTORE_BASE64`: Base64-encoded keystore file
- `KEYSTORE_PASSWORD`: Keystore password
- `KEY_PASSWORD`: Key password
- `KEY_ALIAS`: Key alias

### Firebase Deployment
- `FIREBASE_TOKEN`: Firebase CLI token for deploying Firestore rules

### Generate Required Secrets

#### 1. Android Keystore
```bash
# Create keystore (if you don't have one)
keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

# Convert to base64
base64 upload-keystore.jks | tr -d '\n'
```

#### 2. Firebase Token
```bash
# Login to Firebase
firebase login:ci

# Copy the token and add it as FIREBASE_TOKEN secret
```

## Workflow Jobs

### 1. Analyze
- Runs on every push and pull request
- Creates `.env` file
- Installs dependencies
- Verifies code formatting
- Runs static analysis
- Executes tests with coverage

### 2. Build Android
- Runs after analyze on pushes to main/develop
- Creates `.env` file
- Builds release APK and App Bundle
- Uploads artifacts
- Cleans up sensitive files

### 3. Build iOS
- Runs after analyze on pushes to main/develop
- Creates `.env` file
- Builds iOS without code signing
- Uploads build artifacts

### 4. Deploy Firebase
- Runs after successful Android build on main branch
- Deploys Firestore rules to Firebase

### 5. Release (Optional)
- Triggers on version tags (e.g., v1.0.0)
- Creates GitHub release with APK and App Bundle

## Local Development

### Initial Setup
1. Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```

2. Ensure `firebase_options.dart` exists (generated by FlutterFire CLI):
   ```bash
   flutterfire configure
   ```

### Security Notes
- `.env` is gitignored - never commit it
- `firebase_options.dart` is committed (contains public API keys)
- Keystore files are gitignored
- Firebase Security Rules protect your backend data

## Troubleshooting

### Build Fails with "No file found for asset: .env"
- The CI workflow now creates this file automatically
- Locally, copy `.env.example` to `.env`

### Firebase initialization fails
- Ensure `firebase_options.dart` is committed to the repository
- Run `flutterfire configure` to regenerate if needed

### Android build fails in CI
- Verify all Android secrets are set correctly
- Check that keystore base64 encoding has no line breaks

## Environment Variables

### .env File
- `ALADHAN_API_METHOD`: Prayer time calculation method (default: 2 for ISNA)

### Note on Security
The `.env` file contains only non-sensitive configuration. All actual credentials are managed through:
- Firebase Authentication (user accounts)
- Firestore Security Rules (data access)
- GitHub Secrets (CI/CD credentials)
